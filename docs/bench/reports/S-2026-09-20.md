## O que foi feito

1. **EXPLAIN expandido** — todos os shapes do dashboard em `docs/bench/artifacts/S/` (`dash_*`).
2. **Fan-out SQL** — `getStats` em 3 round-trips (`queryFarmsPack` | `queryCropsPack` | `queryEsg`); `verify-aggregates` PASS.
3. **Índice `farm_crops(harvest_id)`** — **não aplicado**. EXPLAIN de `dash_by_crop` / `dash_climate_by_crop` já usa **Hash Join**; `farm_crops` em **Seq Scan** (~40k rows) é o plano correto para agregação full-table. Sem Nested Loop custoso → índice não mudaria o plano para Index Scan de forma útil.
4. **Split aditivo** — `GET /dashboard/summary` + `GET /dashboard/analytics`; `/dashboard/stats` mantém shape; front progressive; OpenAPI atualizado.
5. **Gates** — `D0_errors` / `L0_errors` / `L1_errors` + cenário `D0s`.
6. **Cache TTL 1.5s + single-flight** — `DASHBOARD_STATS_CACHE_TTL_MS` (default 1500). Micro-bench: vs path sem cache (~576 ms p95) → ~340 ms (**≈41%** > limiar 20% do plano) → **mantido**.

## Limite residual (por que D0_p95 ainda falha)

- Custo cold-path de `/dashboard/stats` (shape completo) é dominado por joins de cultura:
  - `dash_climate_by_crop` ≈ **216 ms** (EXPLAIN)
  - `dash_by_crop` ≈ **113 ms**
  - `dash_crops_by_year` ≈ **119 ms**
- Mesmo com CTE único, o cold compute fica **~300–350 ms**, o que aparece no p95 sob concorrência (ondas de miss após expirar TTL / entre cenários).

- **L0/L1** — hidratação de listagem (fora do fan-out do dashboard); residual conhecido, fora de escopo deste plano.
- Bundle entry 80 KB / scale M-L / auth — fora de escopo.
